# Folder UI

The AI Second Brain workspace uses folders as the primary application surface. Each folder has a stable ID, numeric sequence, key, icon, tab color, document style, child folders, document pages, files, and sticky notes.

## Architecture

- `src/folder-ui/types.ts` — domain models.
- `src/folder-ui/registry.ts` — folder, tab, and document registries.
- `src/folder-ui/store.ts` — reactive workspace state and persistence orchestration.
- `src/folder-ui/indexeddb.ts` — browser persistence adapter.
- `src/folder-ui/FolderWorkspace.tsx` — workspace UI.
- `src/folder-ui/fileRegistry.ts` — universal file-type registry.
- `src/folder-ui/dragDrop.ts` — drag/drop payload and ordering helpers.
- `src/folder-ui/documentEditor.ts` — editable document operations.
- `src/folder-ui/stickyNotes.ts` — sticky-note model and mutations.
- `src/folder-ui/importExport.ts` — JSON workspace import/export.

## GitHub Pages

The GitHub Pages application remains the web client. Folder state is stored locally in IndexedDB so the UI remains useful offline. Deployments should be generated by the repository's Pages workflow after each pushed change.

## File handling

Source code, documents, images, audio, video, archives, spreadsheets, and Windows executables have explicit registry entries. Executables are treated as stored/launchable artifacts and are never treated as editable source files.

## Windows

The desktop build can connect the same folder model to a secure Electron/Tauri filesystem bridge. Browser code must not receive unrestricted Node.js filesystem access.
